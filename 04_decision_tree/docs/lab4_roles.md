# Памятка по ЛР4 «Decision Tree» (группа из 3 человек)

Дисциплина: Системы искусственного интеллекта. Максимум за работу: 10 баллов.

## 1. Суть работы

Предсказываем цену квартиры (`price`) по данным о недвижимости РФ за 2018-2021 гг. (Kaggle, Russia Real Estate). Это задача регрессии. Полный цикл:

1. Предобработка данных по одному региону.
2. Обучение двух линейных моделей: Ridge и SVR (kernel='linear').
3. Обучение решающего дерева (DecisionTreeRegressor).
4. Подбор гиперпараметров через GridSearchCV (5 фолдов, метрика r2).
5. Сравнение моделей по RMSE на тесте.
6. Анализ важности признаков и выводы.

### Ключевые техники

- Обрезка выбросов по квантилям (1% с каждого хвоста).
- Нелинейные преобразования признаков (например, log для `price` и площадей).
- `train_test_split` (test = 30%) и `StandardScaler`, обученный только на train, чтобы не было утечки.
- RMSE как основная метрика, r2 как метрика для подбора параметров.
- Важность признаков: для линейных моделей модуль весов (`abs(coef_)`), для дерева `feature_importances_`.
- Деревья не требуют масштабирования признаков: сплиты идут по порогам, монотонное преобразование порядок значений не меняет.

### Правила сдачи (из шаблона)

- Нельзя удалять текстовые ячейки шаблона, новые ячейки добавлять можно.
- Нужен рабочий код: ответы без кода оцениваются в 0.
- Нужны письменные выводы в местах «Ваши выводы тут».
- Если кто-то из группы не прошёл устную защиту, баллы не начисляются вовсе. Каждый должен понимать всю работу, а не только свою часть.

## 2. Распределение ролей

| Роль | Задачи | Баллы |
|---|---|---|
| Участник 1 | Задачи 1, 2, 3 | 3 |
| Участник 2 | Задача 4 + подбор параметров для дерева (часть задачи 5) | 2 + ~1 |
| Участник 3 | Подбор параметров для Ridge и SVR (часть задачи 5), итоговая таблица RMSE, задачи 6 и 7 | ~1 + ~1 + 1 + 1 |

Нагрузка выравнивается по характеру работы. У Участника 1 самая объёмная часть по коду и анализу данных (EDA, чистка). У Участника 3 больше формальных баллов, но задачи в основном лёгкие (графики, текст); при этом SVR с GridSearch считается долго. Задача 5 разрезана по моделям (линейные у Участника 3, дерево у Участника 2), поэтому блоки кода не пересекаются, и на защите каждый показывает цельную часть.

## 3. Зависимости и порядок работы

### Граф зависимостей

```
Участник 1: задачи 1-2 ──┬──> Участник 2: задача 4, дерево из задачи 5 ──┐
        │                │                                               │
        │                └──> Участник 3: Ridge/SVR из задачи 5 ─────────┤
        │                                                                v
        └─> задача 3 (параллельно с остальными)            Участник 3: таблица, задачи 6 и 7
```

### Кто кого ждёт

| Кто | Чего ждёт | От кого | Что можно делать, пока ждёшь |
|---|---|---|---|
| Участник 1 | Ничего | - | Начинает сразу. Он критический путь: задачи 1-2 блокируют всех |
| Участник 2 | `X_train`, `X_test`, `y_train`, `y_test`, `X_train_raw`, `X_test_raw` (итог задач 1-2) | Участник 1 | Написать код задачи 4 и GridSearch для дерева на заглушке (любой небольшой датасет), заранее прикинуть время `absolute_error` |
| Участник 3, подбор Ridge/SVR | `X_train`, `y_train` (итог задач 1-2) | Участник 1 | Написать код GridSearch (`np.logspace`, `np.linspace`), подготовить шаблон таблицы RMSE и код графиков важности |
| Участник 3, таблица, задачи 6 и 7 | `best_tree`, RMSE дерева (базовое и после подбора) | Участник 2 | Подготовить код графика для Ridge, написать черновик выводов по линейным моделям |

Ключевые моменты:

- Участник 2 и Участник 3 друг от друга не зависят до самого конца: подбор дерева и подбор Ridge/SVR идут параллельно.
- Участник 1 должен сначала отдать задачи 1-2 и только потом делать задачу 3. Задача 3 никого не блокирует, кроме базовых RMSE для итоговой таблицы Участника 3.
- Единственное место, где Участник 3 ждёт Участника 2, это финальный этап (сравнение, задачи 6 и 7). К этому моменту дерево должно быть готово.
- Самый долгий расчёт, GridSearch для SVR (20 значений на 5 фолдов), нужно запускать сразу после получения данных от Участника 1.

### Рекомендуемая последовательность

1. Участник 1 выкладывает блок кода задач 1-2 (имена переменных зафиксированы, см. раздел 4). Остальные подключают его.
2. Параллельно: Участник 1 делает задачу 3, Участник 2 делает задачу 4 и подбор дерева, Участник 3 запускает подбор Ridge и SVR.
3. Участник 2 передаёт `best_tree` и RMSE. Участник 3 строит итоговую таблицу, задачи 6 и 7.
4. Общая сборка ноутбука в порядке задач 1-7, прогон «Run all», проверка.

## 4. Общие правила

- **Единый seed:** `random_state=42` везде (split, дерево).
- **Утечки:** `scaler.fit` и GridSearch только на train. Тест не используется при подборе параметров.
- **Имена переменных (контракт между участниками):**
  - `X_train`, `X_test`, `y_train`, `y_test`: масштабированные, тип `pd.DataFrame`;
  - `X_train_raw`, `X_test_raw`: немасштабированные, тот же split;
  - `scaler`: обученный `StandardScaler`;
  - `best_tree`: лучшая модель дерева.
- **Единицы RMSE:** если к `price` применялся log, все договариваются, в каких единицах считать RMSE (лучше пересчитать обратно в рубли через `np.expm1` и фиксировать это в тексте).
- **Сборка:** каждый ведёт свою копию ноутбука в Colab. В конце все части переносятся в один ноутбук с сохранением текстовых ячеек шаблона.
- **Порядок защиты:** Участник 1, затем 2, затем 3 (как идут задачи). Каждый должен уметь объяснить общий поток: откуда данные, чем отличаются модели, как читать результаты.

  - Удаляет некорректные записи (нулевые и отрицательные значения, нелогичные площади и этажи, например этаж больше числа этажей).

- **Задача 3:** обучает Ridge и SVR с параметрами по умолчанию, считает RMSE на тесте.

**Выход:**

- Базовые RMSE для Ridge и SVR (для итоговой таблицы Участника 3).

## 7. Участник 3: линейные модели, сравнение, выводы (задача 5 линейная часть + 6 + 7)

**Вход:**

- от Участника 1: `X_train`, `y_train`, `X_test`, `y_test`, базовые RMSE;
- от Участника 2: `best_tree`, его RMSE (базовое и после подбора) и параметры.

**Что делает:**

- **Задача 5 (линейная часть):**
  - Ridge: `alpha` от 1e-3 до 1e3, 20 значений через `np.logspace`.
  - SVR: `C` от 0.1 до 10, 20 значений через `np.linspace`.
  - GridSearchCV с cv=5, scoring='r2', только на train.
  - Переобучает лучшие модели, считает RMSE на тесте.
- **Итоговая таблица:** `pd.DataFrame` с RMSE всех моделей (Ridge, SVR, дерево) до и после подбора. Письменный вывод: какая модель лучше.
- **Задача 6:** горизонтальные бары важности признаков для Ridge (`abs(coef_)`) и для дерева (`feature_importances_`). Сравнивает топ-3 признаков и пишет, совпадают ли они.
- **Задача 7:** выводы:
  1. Какая модель лучшая по RMSE.
  2. Достаточно ли качество для прода: сравнить RMSE со средней и медианной ценой, учесть, что модель обучена на одном регионе.
  3. Как улучшить: для линейной модели новые признаки, взаимодействия, отбор признаков, другая регуляризация; для дерева ансамбли (random forest, градиентный бустинг), тюнинг `min_samples_leaf` и `min_samples_split`, геопризнаки.

**Выход:** итоговая таблица, графики и выводы. Это завершающая часть ноутбука.

Совет по времени: SVR с GridSearch (20 значений на 5 фолдов) может считаться очень долго. Запускайте его сразу после получения данных от Участника 1, не дожидаясь дерева. Если время неприемлемое, допустимо подбирать `C` на подвыборке train с явной пометкой об этом в выводах, а финальную модель обучить на полном train.
